# SF_Networks 1.0.59

Install `SF_Networks1.0.59.jar` as the Networks plugin. This release preserves the existing 289 item IDs, recipes, world/database formats and Java 21 universal plugin baseline for Minecraft 1.21.11 and newer supported Paper/Purpur versions.

## Recipe-Aware Pushers

Network, More and Best Pushers can use per-machine buffer targets of 1–64 recipe batches. Multi-ingredient recipes reserve room for missing ingredient types before adding extra batches. An ingredient counts as present only in a physical input accepted for that item. Matching output or display items cannot unlock additional buffering.

Input discovery is bounded to four present types per tick, alongside the existing four-request transfer budget. Unverified types remain missing conservatively, so recipes with more than eight distinct ingredient types can retain a one-batch cap while other types remain unverified. This conservative cap can persist; buffer targets are ceilings, not promised quantities on every tick.

## Transfer and storage integrity

Destination menu, cursor and player inventory writes use observed results to reconcile accepted quantities. Ambiguous compensation or cross-network destination failures hold affected controllers or destinations for investigation without automatically refunding or world-dropping potentially accepted items.

Producing machines can add more of the same item while a menu deposit is processed. Networks now removes the accepted quantity from the current source and preserves newly produced output; VOID discards only the original unaccepted output. Identity changes, decreases and persistence failures retain their compensation safeguards.

Use InfinityExpansion2 2.0.14 for the separate Dust Extractor synchronization fix.

## Release validation

Publication requires the Legacy/United/Gugu compatibility matrix, strict Java 21 universal build, native Purpur 1.21.11 manager/storage probes, Paper 26.3 API compilation, and native Paper 26.3 builds 176 and 194. Quantum Storage checks include clean shutdown and reload in independent JVM processes. The published JAR is downloaded from the same workflow run that supplied the native probes, and existing release assets remain unchanged.

These checks cover the exercised paths and do not establish server-wide TPS gains or complete coverage of every third-party storage adapter. Production-world rollout remains a separate operational step from this release.
