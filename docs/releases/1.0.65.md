# SF_Networks v1.0.65 — Historical Adventure identity diagnostics

Distinct successor to the unchanged official [Networks v1.0.64](https://github.com/wickidcow/SF_NetworksExp/releases/tag/v1.0.64). This is a proposed release candidate until the exact merged source and all GitHub checks are successful.

## What is fixed

- **Item Differenter** now reports a mismatched Adventure display-name tree even when two Slimefun items share the same Slimefun ID and typed PDC. Previously it could show `isSimilar: false | eq` for an old nested/explicit-bold component versus a modern flat component.
- The read-only comparator also checks the presence and exact Adventure value of `ItemMeta.itemName()` on Paper 1.21.11+ rather than ignoring this second naming channel. The result names are `neq.displayname`, `neq.hasitemname`, or `neq.itemname`, as applicable.
- Every existing Slimefun ID check, model-component comparison, PDC, owner and metadata safety gate remains. No item stack normalization or revised cargo/network/crafter matching is performed. The Item Differenter is diagnostic-only and never approves transfers.

## Regression evidence

- A new real MockBukkit `PLAYER_HEAD` fixture covers the same Slimefun ID with a historical nested Adventure name versus a modern flat name, rich lore, different item-name values and presence, and a matching pair.
- Checks preserve original `ItemStack.serializeAsBytes()`, item amounts, typed Slimefun ID/owner `STRING`, ledger `LONG` and arbitrary `BYTE_ARRAY` PDC, and reject different owners/IDs. The mock-only comparator boundary explicitly models PDC value equality because MockBukkit's copied PDC containers are not Paper's production equals implementation.
- Includes previously merged but unreleased cross-version native and MockBukkit damage-resistance parity tests after v1.0.64; no production damage-resistance classifier was changed.

## Build and scope

- New distinct raw plugin JAR must be `SF_Networks1.0.65.jar`, packaged from an unused immutable `v1.0.65` tag pinned to successful master source, with exact artifact SHA-256.
- Require the full Gradle Java 21 build, Slimefun Legacy / United / Gugu compatibility, Paper 26.3 compiler and native Quantum/drawer/restart checks, and existing source/item/bytecode/packaging guards. No measured TPS/MSPT improvements are claimed.
- Auto Crafter 400-machine performance issue [#111](https://github.com/wickidcow/SF_NetworksExp/issues/111) still needs comparable real profiler and spark samples; deprecation issue [#122](https://github.com/wickidcow/SF_NetworksExp/issues/122) remains open until exact historical 1.21.11 and Paper 26.3 metadata parity is established.

## Important compatibility limit

This release **does not make old Slimefun items stack with new items**, repair QuickShop-Hikari shop templates, change a network item's owner/storage/typed PDC, change blueprint/crafter routing, or rewrite historical inventories. It corrects only the Item Differenter's diagnosis of meaningful name differences. See [core #615](https://github.com/wickidcow/Slimefun-Legacy/issues/615) and draft core PR #616 for systemic migration and source-provenance work.

## Deployment

Back up server/world and plugin data. Install the distinct verified raw v1.0.65 plugin JAR only after its release succeeds, never alongside v1.0.64, retain the previous verified JAR as rollback, and confirm that diagnostic `isSimilar` and mismatch reasons agree when comparing known old/new samples. The canonical Slimefun Legacy 44-addon ZIP and core/Unified projects are not modified here.
