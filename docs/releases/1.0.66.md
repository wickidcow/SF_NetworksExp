# Networks Expansion v1.0.66 — fail-closed Item Differenter diagnostic

Distinct successor to immutable [Networks v1.0.65](https://github.com/wickidcow/SF_NetworksExp/releases/tag/v1.0.65). This release must not be published until its exact merged-source native/compatibility gates pass.

## What is fixed

The read-only **Item Differenter** GUI can explain registered ID, owner PDC, name/lore, custom model, fire/map and many other metadata differences. New or historical item components outside this manually maintained list previously could yield `isSimilar: false | eq`. When the detailed result says `eq` but the authoritative Bukkit `ItemStack.isSimilar` is false, the GUI now reports `neq.unclassified-meta`. Known explanations such as `neq.pdc`, `neq.displayname`, `neq.itemname`, `neq.custommodeldata`, `neq.amount` and blacklisting retain their original precedence. Matching items continue to report `eq`.

The fallback is **display-only**. There is no item rewrite, change to metadata construction, storage, Cargo, networks matching, Auto Crafter recipes or throughput, item model, Slimefun ID, QuickShop records or migration defaults. Never use the fallback as permission to stack two items by ID alone.

## Test and provenance gates

- MockBukkit real `PLAYER_HEAD` fixture: representative `SMALL_URANIUM` typed STRING Slimefun ID and owner, LONG ledger and BYTE_ARRAY metadata. An unclassified glint override yields different Bukkit `isSimilar` and correct warning; all original ItemStack serialized bytes, PDC types and quantities survive the read-only diagnostic.
- Regression verifies equal identities remain `eq` despite different stack quantities, and the existing named PDC/Adventure/blacklist/amount categories are never masked.
- Require exact-head full Gradle Java 21 build, Legacy/United/Gugu compilation, Paper26.3 native 176/194 and Purpur 1.21.11 two-JVM Quantum/drawer restart and conservation tests, source/descriptor checks, unused immutable tag and a downloaded official raw JAR SHA-256 verification.
- This is **not** a fix for actual historical nonstacking or the original real AlbionMC items. Core issue [#615](https://github.com/wickidcow/Slimefun-Legacy/issues/615) owns systemic matching/repair. Networks [#111](https://github.com/wickidcow/SF_NetworksExp/issues/111) still needs live profiler evidence, and [#122](https://github.com/wickidcow/SF_NetworksExp/issues/122) still has unresolved Paper deprecation parity.

## Deployment

Back up world, Slimefun, network/crafting/blueprint and inventory data. Once v1.0.66 is officially verified, replace only the Networks JAR with `SF_Networks1.0.66.jar`, keep the published v1.0.65 JAR as rollback and do not run duplicate copies. Test the read-only Item Differenter with an otherwise identical but component-different pair; check that its mismatch reason and Bukkit's `isSimilar` result agree. No configuration migration is required.

This maintained-addon task does not modify Slimefun Legacy core, Unified, the canonical 44-addon ZIP or existing tags/releases.
