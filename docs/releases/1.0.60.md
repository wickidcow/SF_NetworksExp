# SF_Networks 1.0.60

Networks Expansion 1.0.60 completes the coordinated storage and recipe-control repair series. Install `SF_Networks1.0.60.jar` with InfinityExpansion2 2.0.15 when using IE2 storage and machines. The plugin remains named `Networks`, retains all 289 registered item IDs and existing recipes, and emits Java 21 bytecode against the Paper 1.21.11 API floor.

## Item conservation and recovery

Drawer cursor, player inventory, Quantum Storage and ItemMover transfers now verify the authoritative physical slot before committing the opposite endpoint. Partial inventory writes debit exactly the accepted quantity. Rejected writes preserve the original balance; a setter that writes and then throws is reconciled from its actual result. Reentry and detached menus cannot reuse the owned source. Inventory setters receive independent copies, so modifying a write argument cannot alter its expected receipt or authorize a false transfer.

Drawer template registration preserves a flushed exact-identity recovery record before accepting a new item type. Pending amount writes survive rejected or cancelled database work and are checkpointed during shutdown. Invalid negative or overcapacity saved records remain available for recovery instead of being clamped, deleted or treated as ordinary overflow. Intentional Void Excess still applies to valid input overflow.

ItemMover prepares its complete item identity and long balance together, verifies real menu/hand writes and keeps an unresolved receipt when an external adapter cannot prove its outcome. Existing storage keys are retained; new recovery evidence is additive. An ambiguous receipt is not an instruction to guess an identity, refund items or erase a balance.

## Recipe-Aware Pushers

Classic, More and Best Pushers retain per-machine ON/OFF controls and targets of 1–64 batches. Left-click toggles the mode; right-click accepts a numeric target in chat; shift-left/right decreases/increases the target. Settings persist across restart.

Physical input declarations are used for compatible dynamic machines such as Electric Smeltery. Full input stacks count toward the buffer even when the machine's current insertion routing omits them. Re-enabling the mode preserves a larger existing OFF-mode buffer without requesting extra ingredients. Fresh item-aware insertion permissions and missing-ingredient safeguards still control every transfer.

A real item already occupying the control slot remains recoverable. Breaking the pusher is cancelled until that item is removed. Recognized control icons and ordinary empty-slot breaks keep their established behavior.

## Performance and compatibility

Line transfers reuse target classification within a pass, skip work for confirmed missing sources and stop capacity scans when the requested amount is covered. Operation-count regressions verify these reductions while preserving routing and quantity budgets. They do not establish a server-wide TPS percentage.

GuGu Slimefun Legacy is the maintenance target. The existing compatibility gates, strict universal build, Paper 26.3 API compilation and native Paper/Purpur checks remain enforced. Coordinated fixtures exercise storage restart, actual Grid/crafting and IE2 player actions, Drawer/Quantum operations, recipe controls and ItemMover recovery. Exact accepted source revisions, test counts and artifact hashes are recorded in `NETWORKS_EXPANSION_COMPLETION.md`.

Folia runtime support remains unclaimed because multi-chunk network transactions have not been made safe across independent regions. The plugin does not enable itself on Folia merely by adding a descriptor flag. Native clean restart and synchronous receipt verification do not claim atomic recovery from an arbitrary process crash. Existing ambiguous storage incidents still require reconciliation using preserved evidence.
